# Trae + WorkBuddy + Qoder 每日签到 · Cloudflare Worker（增强版）

把三个平台的每日签到搬到云端：**不用开电脑、不用装客户端、不用守时间**。各登录一次把账号托管进去，之后 Worker 自己续期令牌、按时签到，签完给你发消息。

全部代码在 `worker.js` 一个文件里，没有构建、没有依赖，粘进 Cloudflare 网页控制台就能跑。

|        | Trae         | WorkBuddy | Qoder              |
| ------ | ------------ | --------- | ------------------ |
| 加账号    | 抖音扫码         | 微信扫码      | 官网设备授权（国内版）        |
| 签到内容   | 每日积分领取       | 每日签到      | 每日活动领取（credits）    |
| 列表显示   | **剩余积分、最早到期** | **剩余积分、最早到期** | 余额、本次到账           |

三个平台共用一套部署、一个 KV，数据按 `trae:` / `wb:` / `qoder:` 前缀隔离。

> **第一次装？看 [INSTALL.md](INSTALL.md)** —— 从建 Worker 到验证通知，全程网页操作，约 5 分钟。

> 本项目基于 [ggzhzc/workbuddy-trae-checkin](https://github.com/ggzhzc/workbuddy-trae-checkin) 的部署产物做增强，不是原作的发布版。部署方式、扫码流程、接口逆向成果都归原作者，原作未声明开源许可，如原作者有异议请联系下架。详见上方的**免责协议**第 6 条。

## 本版本相比原作的改动

**1. 修复：定时任务不发通知**

原作的 `scheduled()` 只循环调三个平台各自的签到函数，**从头到尾没有调用 `notifyRun`**。所以 Cloudflare 的 Cron 跑完就静默结束，一条通知都不推；只有手点「全部签到」或外部打 `/cron` 才会发。

本版把定时路径改成走 `runAll()`，和手动按钮同一条链路，签完必发汇总。

**2. 新增：每账号剩余积分 + 到期时间**

原作账号表的「累计」是本工具自己记的领取量，不是余额。本版直接查平台的资源接口：

| 平台 | 接口 | 剩余积分 | 到期 |
| --- | --- | --- | --- |
| Trae | `user_current_entitlement_list` | `total_balance` | 逐包 `expire_time`，取最早 |
| WorkBuddy | `get-user-resource-summary`（**注意没有 `/v2` 前缀**） | `TotalCredits` | packages 的 `DeductionEndTime` |
| WorkBuddy | `get-user-resource-free/paid-packages` | `Accounts[].CapacityRemain` | 同上 |
| Qoder | `me/campaigns` | 活动额度字段 | `endTime` |

一个账号通常有十几个积分包、到期日各不相同，所以显示的是「还有余额的包里最早过期的那一个」，点开行内明细能看全部。

**3. 新增：收益趋势**

每轮签到后把当日数据写进 KV `hist:log:{platform}`，滚动保留 120 天。前端画 30 天到账折线，配今日到账、连签天数、异常数。

**4. 新增：通知结果可见**

每次通知的结果写进 KV `notify:last`，页面右上角显示「通知 23:37 已发 / 失败」。发没发一眼能看出，不用猜。

## 一、部署

全程在 Cloudflare 网页控制台完成，不用装工具、不用命令行。

1. [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → **Create**，起个名字（如 `signin-all`）
2. 点 **Edit code**，把 `worker.js` 全文粘进去 → **Deploy**
3. 回 Worker 设置页，加这几个绑定：

| 类型 | 名称 | 值 |
| --- | --- | --- |
| KV Namespace 绑定 | `KV` | 先到 **Storage & Databases → KV** 建一个命名空间，回来选中 |
| Secret | `MASTER_KEY` | 32 字节随机值的 base64，用来加密所有令牌 |
| Secret | `ADMIN_TOKEN` | 你自己定的**页面登录密码** |

生成主密钥：浏览器 F12 → Console 里跑

```js
btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(32))))
```

> 结果一定是 **44 个字符、以 `=` 结尾**。`MASTER_KEY` 丢了 = KV 里的令牌全解不开，只能重新扫码，**存进密码管理器**。

4. **Settings → Triggers → Cron Triggers** 加至少一条：`10 0 * * *`（北京 08:10）

## 二、添加账号

打开 `https://<你的 Worker>.<子域>.workers.dev`，输入 `ADMIN_TOKEN` 登录，按平台添加。

### Trae：抖音扫码

点「添加账号」→ 抖音扫码确认 → 浏览器会跳到一个**打不开的** `127.0.0.1` 页面（正常）→ 复制地址栏整段链接，回控制台粘到右侧输入框（粘贴即生效）。

> 粘的是扫码之后那个 `127.0.0.1:xxxx/...` 的地址，不是前面授权页的地址。

### WorkBuddy：微信扫码

点「添加账号」→ 新窗口打开官方登录页 → 微信扫码确认 → 账号自动出现，窗口自动关闭。二维码约 5–6 分钟有效。

> 官方登录页禁止被内嵌，所以是新窗口而不是内嵌弹窗。

### Qoder：国内版设备授权

点「添加账号（国内版）」→ 在新窗口登录并确认授权 → Worker 轮询到结果后自动入库。

## 三、控制台

顶栏「今日已签」是三个平台合计；「全部签到」三个平台一起跑；标签页分别管理。

本版在标签页上方多了两张卡：

**各账号剩余积分**：顶部是三个平台的合计，下面可滚动列表逐账号显示「剩余积分 + 还剩几天到期」。点击任意一行展开积分包明细（每包剩余 + 到期）。快到期的（≤7 天）标黄，过期的标红，长期包显示「长期」。

**收益趋势**：三个平台各一格，显示剩余/累计、今日到账、连签天数、近 30 天到账折线。右上角是上次通知的状态和时间。

账号状态含义同原作：

| 状态 | 含义 |
| --- | --- |
| 已签 | 今天签上了，下方显示到账金额 |
| 今日未签 | 还没跑，或还没到定时时间 |
| 无可领 | 接口通了但没有可领项 |
| 限流 N 分钟 | 服务端限流，已按账号冷却，到点自动重试 |
| 待确认 | 提交成功但没收到回执，下一轮再查 |
| 签到失败 | 请求出错，下方显示原因 |
| 令牌失效 | 登录态失效，删掉重新添加 |

## 四、定时任务

Cloudflare 的 Cron **只认 UTC**，换算是 **北京 = UTC + 8**。

| 设置 | Cron | 北京时间 |
| --- | --- | --- |
| 必设 | `10 0 * * *` | 08:10 |
| 可选 | `37 15 * * *` | 23:37 |
| 可选 | `17 4 * * *` | 12:17 |

配置位置：Worker → **Settings → Triggers → Cron Triggers → Add**。

> 签到接口幂等，多跑几次不会重复加分。每跑一次都会发一条通知——不想一天收三条的话，只留 `10 0 * * *` 就够了。

## 五、通知设置

控制台右上角「通知」按钮里填，两种通道可同时开：

- **Telegram**：填 Bot Token 和 chat_id
- **QQ 机器人**：填 AppID、Secret、openid（C2C 私聊）

配置用 `MASTER_KEY` 加密后存在 KV 的 `notify:config`，不落明文。填完可以点「测试」发一条样例消息。

> **QQ 官方机器人有主动消息配额**，配额用完那一条就推不出去。看重「每天必达」的话，让 Telegram 当主通道。

## 六、常见问题

**定时任务为什么不发通知？**
原作 bug：`scheduled()` 从不调 `notifyRun`。本版已修。如果你的实例还是不发，先看页面右上角有没有「通知 HH:MM 失败」——有就是发出去但对方拒收，没有就是压根没跑。

**余额和客户端显示的差几十？**
接口返回的是实时值，页面有 2 分钟缓存（点右上角时间可以强制刷新）。客户端可能把不同来源的包分开算，或者你刚用掉了一些。点开账号行看积分包明细，能对上是哪一个包。

**为什么 WorkBuddy 显示「累计」？**
如果拿的是签到活动接口，`total_credits` 是活动期内累计领取量。本版已改成读 `get-user-resource-summary` 的 `TotalCredits`，那才是真余额。页面上「剩余」和「累计」两个词是有意区分的。

**`MASTER_KEY` 丢了会怎样？**
所有账号令牌解不开，等同于全部要重新扫码。没有后门，也找不回来。

**我只想要原作的功能，不要这些增强？**
用 `baseline/worker.baseline.js`，那是打补丁前的产物，直接部署即可。

## 附：命令行部署（可选）

网页控制台够用。想用命令行的话：

```bash
wrangler deploy --no-bundle
```

**`--no-bundle` 必须加**：`worker.js` 已经是打包产物，再让 esbuild 处理一遍只会引入风险。

用 `wrangler.toml` 部署时，**必须把线上所有 binding 都声明全**（KV、plain text 变量）。Secrets 不用声明，部署时不会被删。`wrangler.toml` 里的 KV id 全是占位符，换成你自己的（`wrangler kv namespace create KV` 会返回）。

### 重新生成 worker.js

补丁是打在打包产物上的，不是源码：

```bash
python tools/patch.py baseline/worker.baseline.js worker.js
```

脚本逐处校验锚点唯一性，失配就 `ANCHOR FAIL` 退出，不会产出半成品。
